# Revision after the TMLR desk rejection

The editor gave three reasons. Each is addressed below with what changed and
what deliberately did not.

## 1. Affiliation disclosure in the Declarations block

The submitted PDF carried an Elsevier-style `Declarations` / `Use of Generative
AI` / `Data Availability` block, inherited from the BSPC version. It named no
author directly, but it is not TMLR's format, and two of its sentences point at
the authors regardless: *"Model checkpoints are available from the corresponding
author on request"* and *"the record is not linked here because it identifies the
authors."*

**Applied.** The whole block is gone from `main_tmlr.tex`. TMLR's Broader Impact
Statement covers what it covered; availability is now stated anonymously inside
`\subsection{Reproducibility and availability}` (§3.7). `declarations_preprint.tex`
is untouched and still used by `main_preprint.tex` for arXiv and the
camera-ready.

**Also applied.** The `\author{}` block in `main_tmlr.tex` is now anonymous in
the *source*, not only in the typeset output. It previously held both names,
both emails and the institution; `tmlr.sty` suppressed it at compile time, so
the PDF was clean, but submitting the LaTeX source would have deanonymised the
paper.

**Also applied — the authors confirmed both upstream repositories are public.**
The supplement's `scripts/` referred to them by directory name (`CSG-SKin`,
`DST-Skin`), named environment variables after them (`CSG_SKIN_ROOT`), and cited
a distinctive upstream path (`cbm_revision/scripts/eval_ood_benchmarks.py`). All
of those are searchable and lead to accounts that identify the authors.

The supplement is now generated by `scripts/build_supplement.py`, which copies
the working code and applies a documented substitution list, then refuses to
write the bundle if any forbidden string survives. The working copies under
`scripts/` and `analysis/` are untouched: they keep their real provenance,
because that provenance is what makes them auditable.

`_repo_paths.py` is the one file not derived by substitution. Blind replacement
left it *misleading* rather than merely clumsy -- it would have searched for a
sibling directory named "the audited classifier repository", silently killing a
lookup path. It has a hand-written anonymous counterpart in
`paper/supplement_overrides/` that resolves the repository by environment
variable or marker file only, and says why the name is absent.

**What this does not do.** The scripts import from the upstream repository
(`src.models.csg_lightning`, `CSGLiteLightning`, `--method csg`,
`checkpoints/csg_lite/`). Renaming those would break the code and misrepresent
what was run, so they stay. A determined reviewer can still follow them
upstream; this removes the casual path, not every path.

## 2. Long submission (18 pages) not justified for an experimental paper

Main content is now **12 pages** (references begin on page 12; 25 pages total
including appendices). Nothing was deleted — every paragraph, float and citation
that left the main text is in an appendix, moved verbatim through the fragment
files in `paper/tmlr/moved/`.

| Moved | From | To |
|---|---|---|
| Six related-work subsections (1,272 w) | §2 | Appendix E |
| Relation-to-literature paragraphs 3–6 (352 w) | §5.3 | Appendix E.7 |
| Study-design pipeline diagram | Figure 1 | Appendix A |
| Full geometry-metric definitions (223 w) | §3.4 | Appendix A.1 |
| Mahalanobis-AUROC-by-rung table, geometry-vs-AUROC scatter | §4.2 | Appendix B |
| Feature-norm and majority-class analyses + figure (194 w) | §4.3 | Appendix B.1 |
| Five-scorer per-rung figure (duplicates Table 3) | §4.4 | Appendix B.2 |
| Scorer-invariance argument (356 w) | §5.2 | Appendix D |

§2 was rewritten as four dense paragraphs citing every reference the six
subsections cited; §5.2 became a 100-word pointer keeping the load-bearing
claim. The `Keywords:` line was dropped (TMLR does not use one). Figures 2 and 6
were reduced from 0.72/0.70 to 0.62 `\linewidth`.

Verified mechanically: zero citations lost, zero numeric values lost, zero
duplicate labels, zero undefined references.

## 3. Code submission was figure code, not experiment code

The old bundle shipped three files — `analyze_power_and_ci.py`, `analyze_e1.py`,
`reproduce_power_figure.py` — and its README opened with *"No GPU, no
checkpoints, no dataset download."* The editor read that correctly: the pipeline
that produced the results was not in it.

**Applied.** `paper/supplementary_materials/` is rebuilt in four directories,
ordered by what the editor asked to see first:

- `scripts/` — the experiment pipeline, new to the bundle: embedding extraction
  from an explicitly named checkpoint, the geometry-metric library, Mahalanobis
  fitting and scoring, and the cosine / *k*-NN scorers.
- `analysis/` — every statistical analysis reported in the paper, not only the
  power appendix: E1 and E2 trend tests, the five-scorer comparison, the three
  domain probes, the distance/norm/attractor analyses, and the power and
  interval estimation.
- `figures/` — plotting and table generation only. Nothing here computes a
  reported quantity, and the README says so.
- `results/` — the derived CSVs, including the 13-row checkpoint matrix.

The README now leads with a nine-stage pipeline table mapping each stage to the
file that implements it, the paper section it belongs to, and the CSV it writes,
then states plainly which stages need checkpoints and data (1–3) and which run
from the shipped CSVs alone (4–9).
